> **Release availability:** This page documents the upcoming minor release and the repository implementation. The currently published npm package still uses its previous PostCSS defaults. Keep its separate import/Panda/adapter chain until upgrading to the new minor, then follow the [migration steps](/migration/#upgrade-to-the-zero-option-postcss-pipeline).

## One plugin, three stages

`weapp-pandacss/postcss` enables **CSS import expansion → official Panda generation → adaptation** without options. Install Panda, its explicit presets and the adapter; the importer is an adapter runtime dependency:

~~~sh
pnpm add -D @pandacss/dev@2.2.0 @pandacss/preset-base@2.2.0 @pandacss/preset-panda@2.2.0 weapp-pandacss@^2 postcss
~~~

Keep `weappPanda()` and `polyfill: false` in `panda.config.ts`, import a global `.css` layer entry, and run Panda codegen before your build. Zero options simplify PostCSS registration; Panda's extraction and generated runtime setup still apply. The PostCSS integration also regenerates styles. Do not also register `@pandacss/dev/postcss` or a second `postcss-import`; duplicate Panda and incorrect external stage order are reported before generation.

~~~js
// postcss.config.cjs
module.exports = {
  plugins: {
    'weapp-pandacss/postcss': {},
  },
}
~~~

Unit conversion is built in and opt-in: `units` defaults to `false`, with no ratio inferred from the target. Enable it on the same plugin when needed:

~~~js
module.exports = {
  plugins: {
    'weapp-pandacss/postcss': {
      units: {
        rules: [{ from: 'rem', to: 'rpx', factor: 32 }],
      },
    },
  },
}
~~~

This converts `0.5rem` to `16rpx` after complete adaptation and before framework
postprocessing, without installing another converter. Rules accept string, regex,
or function matchers, custom factors and signed callbacks. Supply the font,
container, or viewport basis for relative units yourself. Empty options preserve
source units. See [all unit options and matching boundaries](/api/postcss-plugin/#built-in-unit-conversion).

## Options

The table below lists common settings. The [PostCSS API reference](/api/postcss-plugin/) covers every field, nested csstools option, mode selection and diagnostic.

| Option | Default | Behavior |
| --- | --- | --- |
| `imports` | `true` | Expands CSS imports; accepts importer options or `false` |
| `panda` | `true` | Generates Panda CSS; accepts Panda PostCSS options or `false` |
| `adapter` | `true` | Encodes selectors and applies the selected target transforms |
| `units` | `false` | Built-in generic conversion via `UnitConversionOptions`; no inferred ratio |
| `target` | `weapp` | Mini-program platform transforms; `web` preserves Web semantics |
| `disabled` | `false` | Bypasses every stage, including imports, Panda, adaptation and units |
| `cascadeLayers.mode` | `ordered` | Compiles layer order; explicit `legacy` retains the old pipeline |
| `cascadeLayers.onConflict` | `warning` | Warns about potential semantic differences; `error` fails the build |
| `selectorReplacement.root` | `page` | Replaces `:root` and `:host` |
| `selectorReplacement.universal` | `['view', 'text']` | Replaces `*` |

## Stage switches and project discovery

The same entry supports custom pipelines. Adapter-specific options remain at the top level:

~~~ts
import adapter from 'weapp-pandacss/postcss'

adapter() // imports → Panda → default weapp adaptation
adapter({ target: 'web' }) // imports → Panda → portable Web CSS
adapter({ imports: false, panda: false }) // adapter only
adapter({ adapter: false }) // imports → Panda, native selectors and layers
adapter({ adapter: false, units: { rules: [{ from: 'rem', to: 'px', factor: 16 }] } }) // still converts units
adapter({ disabled: true }) // bypass the complete pipeline
adapter({
  imports: { skipDuplicates: false },
  panda: { cwd: '/absolute/app', configPath: 'panda.config.ts' },
})
~~~

Disable a stage only when another part of the build owns it. For example, an external official Panda plugin requires `panda: false`; it must run before the adapter. A custom external importer requires `imports: false` and must run before Panda generation. Avoid manually registering both an internal and external instance of the same stage. Taro may append its own importer after project plugins: this is allowed while the built-in importer is enabled and has already expanded the graph. If `imports: false` makes that external importer the only owner, it must precede Panda and adaptation.

Panda configuration discovery uses explicit `panda.cwd` / `panda.configPath` first, then the nearest config above the actual source CSS file, then discovery from `process.cwd()`. For a discovered config, its containing directory is the project root, keeping `include` and `outdir` local to that project. An explicit invalid config is an error and does not fall back to another project. Monorepo processors can process files from different applications without sharing a guessed root.

For custom loaders, pass the real entry path as PostCSS `from`; a virtual module ID is not a physical file. The plugin preserves original node locations, source maps, importer/Panda dependency messages and warnings. Forward those messages to the framework watcher. Without a genuine file context, a CSS string can still be adapted, but official Panda generation skips it; relative imports require an appropriate real `from` or explicit `imports.root`.

## Sass, Less and Stylus

The order is **framework preprocessor → imports → Panda → full adaptation → built-in units (when enabled) → framework postprocessing**. Install/configure the preprocessor through the framework. Keep the global Panda layer entry as `.css`: official Panda 2.2.0 processes CSS filenames, even when a framework has already compiled a `.scss` entry to CSS text.

Sass `@use`/`@forward`, Less variables/mixins and Stylus syntax belong to their respective compiler. The built-in importer expands CSS graphs; its default loader rejects raw `.scss`, `.sass`, `.less`, `.styl` and `.stylus` imports instead of passing uncompiled syntax into WXSS. Import their compiled CSS, let the framework resolve them first, or supply `imports.load` with a real compiler and watch integration. `imports.plugins` can apply PostCSS transformations to each imported CSS file. A custom loader is responsible for returning valid CSS and reporting its extra dependencies.

A preprocessor may deliberately preserve an ordinary CSS `@import`; the internal import stage expands it afterward. If CSS nesting remains, configure a nesting transform before adaptation. The plugin adds no Sass/Less/Stylus compiler or default unit ratio. `units` converts their compiled CSS, plus Panda-generated and imported styles in the same root.

## Cascade layer compatibility

Mini-programs default to `cascadeLayers: { mode: 'ordered', onConflict: 'warning' }`. Ordered compilation uses the pinned `@weapp-tailwindcss/css-compat@0.1.1` core behind the adapter; applications do not need to import that package directly. The compiler registers layer names in first-declaration order, flattens nested/anonymous/repeated layers, and emits ordinary selectors without generated `:not(n)` specificity placeholders. Normal declarations follow layer order, then unlayered declarations. Important declarations use the reverse order, with unlayered important declarations first. Source order inside each layer is preserved.

This provides **order compatibility**, not a complete native-layer polyfill. In WXSS, a lower-priority layer with a more specific selector can still override a higher-priority layer. The adapter reports potential conflicts through PostCSS warnings, with layer names, selectors, properties and source positions. Shorthands, logical properties and unknown functional selectors are analyzed conservatively; a warning does not prove that both selectors match a real element. Set `onConflict: 'error'` to fail the build on these diagnostics.

```js
export default {
  plugins: {
    'weapp-pandacss/postcss': {
      cascadeLayers: { mode: 'ordered', onConflict: 'error' },
    },
  },
}
```

Declare the full layer order outside conditional blocks before using layers in `@media` / `@supports`. Source CSS can use ordinary `@import`, including layer-qualified imports. Expand the complete import graph and CSS nesting before the adapter. **Any remaining `@import` fails ordered compilation**, including plain and remote imports, even if the current file has no layers: unseen imported rules can change layer order or unlayered precedence. `postcss-import` leaves remote imports in place, so vendor those styles locally or use an earlier resolver that expands them. Never delete imports just to silence the check. `revert-layer`, unexpanded preprocessing syntax, invalid layer structures and already-polyfilled layer placeholders also fail. Keep Panda `polyfill: false`; regenerate CSS from its original layers. Web/H5 (`target: 'web'`) always retains native layers.

The existing `WP_LAYER_SPECIFICITY`, `WP_LAYER_CONDITIONAL_ORDER` and `WP_LAYER_SELECTOR_UNKNOWN` text prefixes remain compatible. Structured PostCSS warnings use the core's `LAYER_*` codes and include the original diagnostic and source location; strict mode throws a PostCSS `CssSyntaxError` with diagnostics and its cause. Descriptor order and unfamiliar wrapper semantics can add compatibility warnings, promoted to errors by `onConflict: 'error'`. Legacy still uses the existing csstools pipeline, not the shared package's `/legacy` entry. Existing adapter fields and legacy selection remain supported; the new stage switches enable the composed pipeline by default. Runtime and class encoding keep their existing contract. See the [PostCSS API](https://panda.weapp.dev/api/postcss-plugin/) for diagnostic handling.

Ordering is local to one PostCSS root. Combine layered inputs before adaptation if their relative layer order matters; independently compiled files and isolated component styles do not share a global layer registry. The Wevu example uses shared application WXSS and explicitly declares component `styleIsolation: 'apply-shared'`.

Existing 2.x options remain supported: explicitly passing `removeNegationPseudoClass`, `selectorReplacement.cascadeLayers` or `cascadeLayersPluginOptions` selects the legacy pipeline. You can also choose `cascadeLayers: { mode: 'legacy' }`. Legacy is not a strict native-layer polyfill either. Combining an explicit `mode: 'ordered'` with old options is a configuration error. Ordinary authored `:not(...)` is preserved.

`isPseudoClassPluginOptions` still configures the csstools `:is()` transformation. No runtime or class-encoding change is required for this migration.

## Web/H5

~~~js
'weapp-pandacss/postcss': { target: 'web' }
~~~

Register the Panda plugin for Web too. The same runtime class names work across targets without rollback.

Keep CSS source selectors in their original form, using normal CSS escaping. Do not feed encoded CSS back as unmarked source or remove the portable-generation marker.

`disabled: true` is a complete opt-out: a portable runtime combined with unencoded CSS can no longer match. Use it only when the stylesheet does not need adaptation or when another pipeline owns the matching runtime.
