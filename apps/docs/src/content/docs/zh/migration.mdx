本页包含原 2.0 迁移和下方共享 ordered 内核更新。2.0 改变 class 编码与默认变量命名，旧 runtime、页面产物不能与新生成 CSS 混用。迁移将生成文件补丁替换为 Panda 插件，不只是修改一个导入。

## 升级顺序

1. 停止项目中写入生成目录的 build/watch 进程，删除旧 `styled-system` 产物，包括 helper 备份与 weapp-panda 补丁文件。
2. 固定 `@pandacss/dev`、`@pandacss/preset-base`、`@pandacss/preset-panda` 为 **2.1.2**。注册 `weappPanda()`，设置 `polyfill: false`，使用支持的 `.js` 或 `.mjs` runtime 输出。
3. 将 `panda codegen && weapp-panda codegen` 改为 `panda codegen`，移除 adapter 子进程、`codegen:done` 补丁 hook 和跨平台 rollback 脚本。
4. 仅注册 `weapp-pandacss/postcss: {}`，由它执行 import 展开 → Panda → 适配，按需单位规则配置在同一插件的 `units` 中。旧 adapter 配置文件的 CSS 选项移到此插件参数。
5. 手写 class helper 改用 `@weapp-pandacss/runtime`，只编码原始手写名称一次，保留 `css()`、recipe、pattern 与 `cx()` 结果。
6. 对齐平台环境、生成/输出目录和 alias，再同步生成 runtime 与 CSS。仅清理受影响框架目标的旧缓存，重新构建。
7. 对实际支持的目标检查最终 class、selector、token 引用与真实交互。

不要先 rollback 恢复旧 runtime 再接入新插件。插件在写入前把转换 artifacts 返回给 Panda，不需要 helper 备份或生成后修改文件。

## Panda 配置

~~~ts
// panda.config.ts
import { defineConfig } from '@pandacss/dev'
import { weappPanda } from 'weapp-pandacss/panda'

export default defineConfig({
  plugins: [weappPanda()],
  polyfill: false,
  presets: ['@pandacss/preset-base', '@pandacss/preset-panda'],
  include: ['./src/**/*.{js,jsx,ts,tsx,vue}'],
  preflight: false,
  outdir: 'styled-system',
  outExtension: 'mjs',
  forceImportExtension: true,
})
~~~

完整应用还需采用[安装与快速开始](/zh/get-started/)中的 PostCSS 配置和全局样式导入。源码导入与生成扩展名、目录保持一致。

## 替换手写 class helper

~~~ts
// 替代旧 styled-system/weapp-panda/index.mjs 导入。
import { encodeClassList, encodeClassName } from '@weapp-pandacss/runtime'

const activeClass = encodeClassName('custom/active')
const labels = encodeClassList('a.b 中文')
~~~

原公共入口 `weapp-pandacss/runtime` 继续作为独立实现的兼容转导出，它不同于已删除的内部生成 helper 路径。业务代码使用独立包时，将它安装为业务依赖。

| 原始输入 | 新输出 |
| --- | --- |
| `a.b` | `a_wp_2e_b` |
| `a_wp_2e_b` | `a_wp_5f_wp_2e_b` |
| `1card` | `_wp_31_card` |
| `中文` | `_wp_4e2d__wp_6587_` |

不要在生成文件中全局替换旧转义字符串，猜测新结果。应从原始名称重新生成，让编码器完成转换。详见[类名处理](/zh/guides/class-names/)。

## 已删除的 v1 接口

| v1 接口 | v2 替代方案 |
| --- | --- |
| `createContext`、`inject`、`patch` 与 runtime 文件操作 API | Panda 配置中注册 `weappPanda()` |
| Adapter `defineConfig` 与配置加载器 | Panda 的 `defineConfig`，PostCSS 直接传参数 |
| `UserConfig`、`ICreateContextOptions` 等旧配置类型 | Panda 配置类型与 `IPostcssPluginOptions` |
| `weapp-panda` / `weapp-pandacss` CLI、codegen/init/rollback | Panda codegen 与正常框架脚本 |
| `escapePredicate`、PostCSS `naming` 与旧编码 | Portable 编码与配套完整重新生成 |
| 内部 wildcard 路径导入 | 公共根入口、`/panda`、`/postcss`、`/runtime` 或独立 runtime |

已删除接口没有 deprecated 占位实现，公共签名与导入方式详见 [API 大全](/zh/api/)。

## Layer 与旧 PostCSS 参数

默认 ordered 路径需要原始 `@layer` 信息。Panda 保持 `polyfill: false` 并从源码重建，无法从旧 `:not(#\#)` 权重占位中恢复层顺序。

显式 `removeNegationPseudoClass`、`selectorReplacement.cascadeLayers`、`cascadeLayersPluginOptions` 会选择 legacy 模式。接入 ordered 时移除旧选项，使用 `cascadeLayers: { mode: 'ordered' }`，两者混用会报配置错误。

Layer 转换提供顺序兼容，不是完整原生 cascade 等价。权重告警与单 root 边界详见 [CSS 兼容](/zh/guides/css-compatibility/)，layer 模式选择不会引入另一套 class 编码格式。

## 共享 ordered 内核更新

源码更新将本地 ordered 内核替换为固定的 `@weapp-tailwindcss/css-compat@0.1.1`，记录 **minor 发布意图**，尚不指定或发布新 adapter 版本，实际安装版本以包与 release 为准。已发布指南原本就要求在适配前展开 import 和 nesting；共享内核现在校验**每个残留 import**，包括普通与远程导入，而非只校验带 layer 的导入。

1. 保留源码 `@import`，按 [PostCSS 流水线](/zh/postcss/)或框架 importer 在 Panda、adapter 前合并完整导入图，不删除 import 绕过校验。
2. Taro React/Vue、React Vite、Weapp Vite 都使用默认三合一 PostCSS 插件。Uni-app Panda 虚拟入口传真实 `pandaEntry` 文件名，向 watch 透传导入与 Panda 依赖；H5 在该阶段使用 `adapter: false`，随后仅执行 Web 适配。
3. 远程样式放到本地或使用前序解析器，`postcss-import` 会保留远程 import。适配前展开 nesting 与预处理语法，`revert-layer` 改为明确规则。
4. 保留公开参数与 legacy 选择。原三个 `WP_LAYER_*` 文本前缀不变，程序诊断提供 `LAYER_*` code、源码位置及上下文；新增 descriptor/wrapper 兼容警告可能让 `onConflict: 'error'` 拒绝更多高风险输入。
5. 为全部支持目标重新生成、构建，检查导入特殊 class 的编码、普通未分层优先级、important 逆序及导入文件修改后的更新。H5 保留原生 layer；小程序 ordered 编译前应已展开源码导入图，编译器移除该 root 的 layer。框架后续可生成合法 WXSS import 来加载独立编译资源，这些产物导入不属于输入校验。

无需 runtime 迁移、命名 rollback 或业务直接安装 CSS compat。严格/input 失败由 PostCSS `CssSyntaxError` 携带结构化诊断；原子校验仅保证独立 layer 阶段，不包含 adapter 前面的全部变更。症状与检查详见[排错指南](/zh/troubleshooting/#普通-import-现在构建失败)。

## 升级到零选项 PostCSS 流水线

本次 minor 更新让现有 PostCSS 入口默认组合 import、官方 Panda 与适配。删除单独的 `postcss-import` / `@pandacss/dev/postcss` 注册，改为：

~~~js
module.exports = {
  plugins: { 'weapp-pandacss/postcss': {} },
}
~~~

保留 `panda.config`、`weappPanda()`、`polyfill: false`、显式 Panda 2.1.2 preset、全局 `.css` layer 入口与 codegen 脚本。H5 使用 `{ target: 'web' }`，单位转换通过内置 `units` 按需启用。自定义流程可关闭对应内置 `imports`/`panda` 阶段后保留外置插件，或用 `{ imports: false, panda: false }` 仅执行适配。`disabled: true` 现在跳过整个组合流水线，`adapter: false` 则仍导入、生成 CSS 并执行显式配置的 units。

Panda 先发现真实源文件附近最近配置，再从进程 cwd 回退；显式覆盖放在 `panda` 下。自定义 loader 使用真实 `from` 并转发依赖消息。Sass/Less/Stylus 仍由框架预处理，Panda 入口保持 `.css`。默认 importer 拒绝原始预处理文件导入，不推断编译器或单位比例。重新构建各目标，验证 watch 更新、class/selector 匹配和 H5 原生 layer，详见[完整接口](/zh/api/postcss-plugin/)。

## 内置单位转换 minor 更新

单位转换现在属于现有 PostCSS 入口。移除独立转换器注册与依赖，把原比例迁入
`units`；不需要转换时保留空配置。微信与 Web 都不会按平台推断比例：

~~~js
module.exports = {
  plugins: {
    'weapp-pandacss/postcss': {
      units: { rules: [{ from: 'rem', to: 'rpx', factor: 32 }] },
    },
  },
}
~~~

单位阶段在完整适配生命周期之后、框架后处理之前执行。px 仍由 Taro 负责时，
保留 `pxtransform` / NutUI `designWidth`；自定义 units 接管 px/rpx 时关闭重叠
转换。Uni 虚拟 Panda 入口 `units: false`，最终框架阶段只转换一次；Tailwind
通过 `adapter: false` 仅转换单位，保留自己的命名。`disabled: true` 关闭全部
阶段，`adapter: false` 则保留显式 units。

默认 CSS tokenizer 修复符号与科学计数法，保护完整单位、字符串、URL、标识符及
深层 `var()` fallback。回调接收带符号数值，`minValue` 按绝对值比较。检查自定义
`unitRegex` 与多次处理的规则：首匹配即最终选择，单轮不连锁，重复处理仍可能转换。
根入口提供 `unitPresets`、`composeUnitRules` 与完整类型，无需额外安装。详见
[完整单位 API](/zh/api/postcss-plugin/#内置单位转换)。

## Web/H5 与构建隔离

Web/H5 保留 `weappPanda()` 和三合一 PostCSS 插件，使用 `target: 'web'`，保留原生 layer/selector，同时共享 portable class 命名，无需 runtime rollback。

Taro 示例使用 `styled-system/weapp` 与 `styled-system/h5`，输出位于 `dist/<平台>`；Uni-app 使用 `styled-system/mp-weixin` 与 `styled-system/h5`，最终目录还区分 dev/build。平台先于 codegen 设置，`styled-system` 解析到对应目标，两个写入进程不能共用生成目录。

Uni-app Tailwind 对比示例分开维护 Panda/Tailwind 流程，新 portable 编码不能替代 Tailwind 的 runtime 命名。环境、alias、watch 与缓存处理详见[多目标构建](/zh/guides/build-targets/)。

## 兼容边界与完成条件

| 能力 | 边界 |
| --- | --- |
| Panda 生成 | 仅 **2.1.2**，覆盖 codegen 与 PostCSS 自动生成 |
| 生成 runtime 扩展名 | `.js` / `.mjs`，拒绝 TS-only、未知或不完整结构 |
| Portable 生成范围 | `css`、`cva`、`sva`、命名/slot recipes、compounds、patterns 与 styled 元数据 |
| Runtime 行为 | `cx` 保持拼接，原始样式对象与元数据保留 Panda 语义 |
| 业务 JS | 框架负责为目标 runtime 打包与转译 |
| 源码原始 class 内联 | 绕过生成 runtime 的流程不支持 |
| 包消费 | ESM/CJS 公共入口及对应声明 |
| CSS 再次处理 | 保留 portable 生成标记 |

确认干净构建、第二次 codegen、recipe/slot 状态切换及最终 token 声明。需要时在真实 IDE/设备验证，源码覆盖率和产物匹配不能证明像素布局。某阶段失败时，按[故障排查](/zh/troubleshooting/)定位，不要保留新旧混合产物。
