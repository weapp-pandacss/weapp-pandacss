## 从最终产物开始

沿着“源码样式 → Panda 提取 → 生成 runtime → PostCSS CSS → 框架产物 → 实际节点”检查，找出 class、规则或值最先丢失的阶段。修改编码不能修复未导入的样式、提取失败或 JavaScript 编译错误。

| 症状 | 首先检查 |
| --- | --- |
| Panda 拒绝生成 | 安装版本与完整生成产物约定 |
| 有 class，无规则 | 源码扫描、codegen、样式导入与目标目录 |
| 页面有效，组件失效 | 样式隔离与最终组件作用域 |
| 仅动态值失效 | 静态提取与有限变体生成 |
| `Unexpected token ?`、optional chaining 错误 | 最终 AppService JS 与框架转译 |
| H5 正常，微信异常 | CSS target、单位、渲染器与最终 WXML/WXSS |
| 切换目标后恢复旧产物 | 环境、alias、输出目录与缓存归属 |

## Panda 版本或 runtime 不支持

**症状：** 出现 `weappPanda requires Panda CSS 2.1.2`、不支持的 runtime、缺少 helpers/sva 或 TS-only 输出诊断。

**根因：** 插件依赖已验收的 Panda 产物结构，不同版本、不支持的扩展名或不完整生成不能安全适配。

**修复：** 固定 `@pandacss/dev`、`@pandacss/preset-base` 与 `@pandacss/preset-panda` 为 **2.1.2**。使用 `outExtension: 'mjs'` 与 `forceImportExtension: true`，也可使用支持的 `.js` 输出。注册 `weappPanda()` 后完整重新生成，旧备份/补丁 hook 按[迁移步骤](/zh/migration/)移除。

**验证：** 重复 codegen 成功，helpers 与 slot runtime 带有 portable 生成标记，不依赖旧 helper 备份。不要吞掉诊断，也不要只修改一个生成文件而保留另一轮产物。

## 有 class，但样式未生效

**症状：** 节点有 class，但看不到对应颜色或间距。

**根因：** 规则没有被提取或加载，导入了另一目标 runtime，class 重复编码，或后续 CSS 胜出。

**修复：** 检查 `include`（需要时包含 `.vue`）、Panda 插件、Panda → adapter 顺序，以及应用入口的全局 layer CSS 导入。确认 runtime 导入与 bundler alias 使用同一目标目录，直接使用生成的 `css()`/recipe 结果，仅对原始手写特殊名称编码。

**验证：** 同时查看实际节点 class 与最终 CSS/WXSS selector。例如原始 `a.b` 两侧均为 `a_wp_2e_b`，原始 `a_wp_2e_b` 则为 `a_wp_5f_wp_2e_b`。已有匹配规则时，继续检查声明、token 值、隔离与竞争权重，而不是修改编码器。详见[类名处理](/zh/guides/class-names/)。

## 页面有效，组件内无效

**症状：** 同一 class 在页面中有效，在自定义组件内失效。

**根因：** 全局 WXSS 被组件隔离，或者框架作用域改变了 selector。

**修复：** Wevu 示例使用 `defineComponentJson({ component: true, styleIsolation: 'apply-shared' })` 接收共享应用样式；原生微信在 `Component({ options: ... })` 中设置 `styleIsolation`。按组件设计选择隔离策略，不要自动把所有组件改成 `shared`。

**验证：** 检查组件实际 class、生成作用域与可访问的样式，同时验证初始与切换后的变体。详见[组件样式](/zh/guides/component-styles/)。

## 动态值没有对应规则

**症状：** `css({ color: runtimeColor })` 返回字符串，但所选颜色没有对应样式规则。

**根因：** Panda 无法提取任意运行时值；命名 recipe 仅来自运行时的变体也可能没有生成 CSS。

**修复：** 有限状态使用 `cva()`/`sva()`，让命名 recipe 的字面量调用可见，或使用 Panda `staticCss` 预生成有限集合。任意值使用静态 `var(--runtime-color)` 表达式与运行时 style 赋值。这属于 Panda 提取问题，不需要额外编码。

**验证：** 每个允许的有限值都存在对应规则；动态变量同时存在静态引用规则与元素赋值。检查 reload 与重复切换，详见[动态样式](/zh/guides/dynamic-styles/)。

## 别名或生成类型报错

**症状：** `Cannot find module 'styled-system/...'`、缺少生成声明或 `.weapp-vite` 支持文件。

**根因：** 尚未 codegen、导入指向另一目录，或全新 Wevu checkout 尚未 prepare 受管类型。

**修复：** 同时设置 TypeScript paths 与 bundler alias。别名替代 Panda 默认导入时，保留对应 `importMap`。Weapp Vite + Wevu 先执行 `wv prepare`，再 Panda codegen，随后运行正常 typecheck/build 脚本。

**验证：** 类型检查和真实框架构建都解析到当前目标的生成文件，编辑器补全不能代替构建验证。详见[多目标构建](/zh/guides/build-targets/)。

## Optional chaining 或 JavaScript 语法错误

**症状：** AppService 报 `Unexpected token ?`、optional chaining/nullish 语法错误，或者无法解析生成 `.mjs` 模块。

**根因：** Panda 生成 runtime 没有进入框架的目标语言编译，或选定运行时无法解析最终语法。Adapter 转换 class 生成逻辑，不负责小程序 JavaScript 转译或语言/API polyfill。

**修复：** 找到最终 JS 及负责它的 loader/preset。Taro Webpack 小程序配置显式将 `/\.[cm]js$/i` 文件交给 `babel-loader` 与框架 preset。核对 target、loader 排除范围及工作区实际解析的 Babel 版本，让 codegen 产物继续作为正常 bundler 输入。所需语法转换/API polyfill 配置在框架边界。

**验证：** 重建并在选定 IDE/基础库运行真实应用，确认 AppService 无解析/运行异常，交互正常。不要修改 helper、文本替换 `?.` 或随机开启 IDE 开关，先查清缺失的实际阶段。

## 小程序尺寸或变量与 H5 不同

**症状：** Class 匹配，但不同目标的尺寸或 token 样式值不同。

**根因：** WXSS 使用了 Web target、rem 转换设置不同、运行时内联样式绕过 PostCSS，或渲染器不支持对应 CSS 能力。

**修复：** H5 使用 `target: 'web'`，小程序 CSS 使用 `weapp`。默认保留单位；在同一插件中配置 `units: { rules: [{ from: 'rem', to: 'rpx', factor: 32 }] }` 可把 `0.5rem` 转成 `16rpx`，比例由项目显式提供。与 Taro `pxtransform` 明确分工，自定义 units 接管 px/rpx 时关闭重叠的框架转换。运行时 style 字符串需直接携带预期单位。

**验证：** 在实际渲染器对照最终声明、引用的 token 变量与 computed/可见结果。Class/selector 匹配不能验证布局，详见[单位设置](/zh/guides/component-styles/#单位与设计比例)。

## 单位没有转换或重复转换

**症状：** 长度仍为 rem、`var()` fallback 不变、导入的第三方样式意外转换，或再次
构建后尺寸继续变化。

**根因：** `units` 默认 `false`，`units: {}` 没有规则，过滤 / 阈值跳过 token，或
默认 tokenizer 保护了 `var()`。展开 import 后，`exclude` 只检查根入口。重复
adapter 阶段仍执行 units，portable 标记只防重复 class 编码；框架也可能转换 px/rpx。

**修复：** 在现有插件上添加显式规则，检查 `propList`、`selectorBlackList`、绝对值
`minValue` 与根入口 `exclude`。在自定义属性声明上换算 token，不依赖 `var()` 内
换算；仅在能自行保证保护边界时使用自定义 `unitRegex`。按导入来源保留值时，在
transform 读取 `context.decl?.source?.input.file` 并返回 `undefined`。为单位指定
唯一处理阶段：Uni 虚拟入口 `units: false`，最终框架阶段只转一次，Tailwind 使用
`adapter: false` 仍保留显式 units。外层 `disabled: true` 也会关闭 units。

**验证：** 用 `-2rem`、`1e-3rem`、自定义属性和 `var()` fallback 组成 fixture，检查
导入来源及同一 processor 处理第二个文件的结果，再对比框架后处理前后与 watch
修改后的产物。详见[单位匹配与选项](/zh/api/postcss-plugin/#内置单位转换)。

## CSS 变量诊断

**症状：** `Unsupported mini-program CSS variable` 指向声明、`var()` 引用或 `@property` 名称。

**根因：** 原始自定义属性名称不符合 adapter 的 ASCII 检查。

**修复：** 手写变量使用 `--[A-Za-z0-9_-]+`。生成变量优先使用 Panda token，`weappPanda()` 启用原生 `hash.cssVar`，使声明与 `token.var()` 引用一致。Adapter 不会重命名任意手写变量。

**验证：** 声明与引用使用同一受支持名称；token 读取实际返回的变量引用，不要自行重建 hash。

## 普通 import 现在构建失败

**症状：** 之前可接受的 `@import "./base.css";` 现在报 `LAYER_IMPORT`，包括入口本身没有 `@layer` 的情况。Importer 保留的远程 import 也会失败。

**根因：** Ordered 内核看不到未解析文件中的规则，普通 import 也可能引入 layer 或优先级更高的未分层普通规则。共享内核校验了指南原本就要求的适配前导入展开。

**修复：** 使用 [PostCSS 配置](/zh/postcss/)中的零选项三合一插件，内置 importer 在官方 Panda 与适配前展开本地 CSS。若有意设置 `imports: false`，确认外部 importer 运行在 Panda 之前。虚拟入口用真实入口路径作为 `from`，而非虚拟 ID。远程 CSS 放到本地或由前序阶段完整解析，不删除 import 来通过校验。

**验证：** Adapter 输入含所有导入规则且无未展开源码 import。检查最终编码 class/selector、普通未分层优先级与 important 逆序，再修改导入文件后重新构建。框架在适配之后生成、用于加载独立编译资源的 WXSS import 不属于这项源码输入检查。

## 插件重复或阶段顺序错误

**症状：** 三合一插件报告重复官方 Panda 注册，或外置 import/Panda 阶段顺序错误。

**根因：** 旧配置单独注册了插件，而三合一入口现在默认启用这些阶段。

**修复：** 普通配置只保留 `'weapp-pandacss/postcss': {}`。必须使用自定义 importer 或 Panda 集成时，关闭对应内置阶段（`imports: false` 或 `panda: false`），并将外部负责者放在消费其产物的阶段之前。`panda.config` 中的 `weappPanda()` 仍需保留，它是生成 hook，不是重复的 PostCSS 注册。 内置 importer 保持启用时，允许 Taro 自动追加的后置 importer，不应为了其他顺序错误删除框架内部处理。

**验证：** 查看最终解析的 PostCSS 插件，从干净目标目录构建。Import 展开、Panda 生成与适配各按预期顺序运行，生成 class 与最终 CSS/WXSS 匹配。

## 预处理导入失败或 Panda 跳过生成

**症状：** 原始 `.scss`、`.less`、`.styl` 导入在内置 importer 中失败，或预处理全局入口保留 Panda layer 声明却没有生成样式。

**根因：** Importer 读取 CSS，不编译其他语言。官方 Panda 2.1.2 也按 `.css` 源文件名过滤；框架编译后的 `.scss` 文本仍保留原文件名。虚拟或无文件输入也可能缺少真实 CSS 生成上下文。

**修复：** 全局 Panda layer 入口保持 `.css`，组件 Sass/Less/Stylus 先由框架编译。导入已编译 CSS、使用框架导入处理，或提供带编译器和依赖的 `imports.load`。自定义虚拟 loader 用真实 `.css` 入口作为 `from`；纯字符串适配可有意跳过生成。显式 Panda 配置错误应修复对应路径，不通过回退隐藏。

**验证：** 检查源码文件名与实际 PostCSS 输入，确认变量、mixin 和 nesting 已编译，并出现已知 Panda 规则。修改多级依赖验证 watch 更新，详见[预处理器边界](/zh/postcss/#sassless-与-stylus)。

## 导入 CSS 未更新或从错误目录解析

**症状：** 构建找不到相对导入文件，或 watch 中修改导入文件后产物仍保留旧样式。

**根因：** 自定义 loader 从虚拟模块 ID/进程目录处理 CSS，丢弃依赖消息或复用旧输出。Layer 内核不解析文件，也不管理 watch 缓存。

**修复：** PostCSS `from` 使用真实入口绝对路径，默认发现入口附近最近 Panda 配置；显式覆盖时用 `panda: { cwd: actualProjectDirectory }`。跟踪入口与导入的文件/目录依赖，依赖变化时使虚拟样式失效并重新处理。复制完整 [Uni-app 接入](/zh/frameworks/uni-app/#与-tailwind-v4-共存)，不要只复制 adapter 调用。

**验证：** 分别从业务与仓库目录构建，watch 时修改多级导入文件，不重启即可看到新声明。Portable 名称不变并继续匹配编码 selector。用同一 processor 重复处理，确认没有沿用旧 layer 注册表。

## Layer、权重或 polyfill 错误

**症状：** 出现已有 `WP_LAYER_SPECIFICITY`、`WP_LAYER_CONDITIONAL_ORDER`、`WP_LAYER_SELECTOR_UNKNOWN` 文本、新增 `LAYER_DESCRIPTOR_ORDER` / `LAYER_WRAPPER_SEMANTICS` 诊断、Panda polyfill 错误，或 nesting/import/`revert-layer`/预处理输入被拒绝。

**根因：** Ordered 转换需要原始 layer 信息，且不能重现每种原生 cascade 关系。

**修复：** 设置 Panda `polyfill: false` 后重新生成，条件块前声明 layer 顺序，在前序阶段展开 import/nesting，跨层保持接近的权重。不要把显式 ordered 与旧选项混用。[CSS 兼容指南](/zh/guides/css-compatibility/#诊断修复)列出各项诊断的对应修复。

**验证：** 查看结构化 warning `code`/`diagnostic` 与实际胜出的声明，三个旧 `WP_LAYER_*` 文本前缀对应共享内核 `LAYER_*` code。严格/input 失败在 PostCSS `CssSyntaxError` 上附 `diagnostics` 和 `cause`，按源码位置及 suggestion 修复原始输入。希望保守风险直接阻止构建时，使用 `onConflict: 'error'`。Layer 排序只覆盖单个 PostCSS root，不包含独立编译文件或隔离组件。

## Web 与小程序构建相互覆盖

**症状：** H5 生成改变了小程序 runtime，或恢复缓存后出现错误平台。

**根因：** 平台变量设置过晚，目标共用 `outdir`/输出目录，alias 指向其它平台，或多个 watcher 竞争写入。

**修复：** Panda 读配置前先设置平台，使用独立生成/输出目录与对应 alias。停止受影响目标的写入进程后再生成，缓存只恢复到原目标。Web 同样保留 adapter，`disabled: true` 会连 class 编码一起禁用。

**验证：** 先分别从干净目标目录串行构建，再仅在路径独立时验证并行，检查各自最终 class、selector 与 token。详见[多目标构建](/zh/guides/build-targets/)。

## Tailwind 或第三方 class 失配

**症状：** Panda 样式有效，库生成的特殊 class 找不到对应 selector。

**根因：** 库 CSS 经过 portable 编码，但其 runtime 仍返回另一种名称，或两个 CSS generator 处理了同一入口。

**修复：** 每套 generator 的 runtime 与 CSS 保持配套。Uni-app 示例隔离 `tailwind.css`，提前展开 Panda 独立虚拟入口。不要把 Panda 编码用于 Tailwind 产物；第三方 CSS 应先检查类名，再选择处理边界。

**验证：** 每套样式系统各选一个实际节点，对照最终 selector 与 token 值。详见[入口隔离](/zh/guides/build-targets/#panda-与-tailwind-入口隔离)。

## 包导入或 Node API 报错

**症状：** `ERR_PACKAGE_PATH_NOT_EXPORTED`、找不到旧 adapter CLI，或业务代码无法解析 `node:` 模块。

**根因：** 使用了已删除的内部路径，或业务 runtime 导入了构建期插件。

**修复：** 使用[公共入口](/zh/api/)。仅需要手写 class 编码的业务代码导入 `@weapp-pandacss/runtime`，也可使用兼容入口 `weapp-pandacss/runtime`；`/panda` 与 `/postcss` 留在构建配置中。v1 adapter CLI 与内部 wildcard 导入已删除。

**验证：** 使用 runtime 入口重新构建业务代码。发布组件需检查与 adapter 配套的 runtime 版本，这两个不同版本体系的包无需版本号相同。

## 开发者工具加载旧产物或拒绝验收

**症状：** 模拟器显示另一目标页面、构建成功但预览失败，或 `test:e2e:devtools` 在预检阶段停止。

**根因：** IDE 项目指向其它输出目录、框架残留旧产物、AppID 缺少所需能力，或真实 IDE 验收前提尚未满足。

**修复：** 核对 `miniprogramRoot` 与当前构建：Taro 使用 `dist/weapp`，Wevu 示例使用 `dist`，Uni-app dev/build 的输出不同。普通预览需要平台能力时，配置项目有权限的 AppID。仓库真实 IDE 测试还需提供绝对路径的已核对稳定 CLI、有权限的真实 AppID、相同的官方稳定/实际 IDE 版本，以及 24 小时内的版本核对时间；该验收入口拒绝游客 AppID。

**验证：** 确认 IDE 实际项目与输出，检查 AppService 错误，relaunch 后重复交互。验收前提与资源清理步骤见仓库[测试策略](https://github.com/weapp-pandacss/weapp-pandacss/blob/main/docs/testing-strategy.zh.md)。Mpcore 逻辑测试、IDE 渲染与实体设备验收是不同证据。
