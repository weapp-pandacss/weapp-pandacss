## 从样式到 WXSS

Panda 插件适配生成的 JavaScript，PostCSS 插件适配对应样式。两侧使用相同的 class 编码规则。

<BuildFlow>
  <FlowStep icon="code" title="编写样式">
    用 `css()` 编写 TypeScript 样式。
  </FlowStep>
  <FlowStep icon="tag" title="生成兼容的 class">
    `c_#0f766e` 转换为 `c__wp_23_0f766e`。
  </FlowStep>
  <FlowStep icon="file-cog" title="对齐 WXSS 选择器">
    PostCSS 输出 `.c__wp_23_0f766e`。
  </FlowStep>
</BuildFlow>

### 1. 编写样式

~~~ts
import { css } from '../styled-system/css'

export const badgeClass = css({ color: '#0f766e' })
~~~

### 2. Panda 生成兼容的 class

~~~text
Panda class:       c_#0f766e
Mini-program/Web:  c__wp_23_0f766e
~~~

在 Taro React 中把 `badgeClass` 赋给 `className`，在 Vue/Wevu 中赋给 `:class`。返回值已经完成编码，可以直接使用。

### 3. PostCSS 输出对应选择器

~~~css
.c__wp_23_0f766e {
  color: #0f766e;
}
~~~

这里的 class 与声明会通过真实 Panda codegen 和 CSS 提取核对。完整样式还包含 Panda 的其他配置层和适配器处理标记。

## 选择构建目标

| 项目 | 小程序 | Web/H5 |
| --- | --- | --- |
| Panda 生成插件 | `weappPanda()` | `weappPanda()` |
| PostCSS target | `'weapp'`（默认） | `'web'` |
| class 命名 | 共用兼容编码 | 共用兼容编码 |
| Cascade layers | 为 WXSS 编译层顺序 | 保留原生 layers |
| 选择器兼容 | 执行有限的平台转换 | 保留原生选择器 |

<Aside title="Panda 配置" icon="file-cog">
  Panda 中设置 `polyfill: false`，让适配器收到原始 layers。[PostCSS 行为说明](/zh/postcss/)介绍冲突与选择器限制。适配器处理命名和部分 CSS 转换，仍需核对目标平台的 CSS 支持情况。
</Aside>

## 兼容范围与迁移

适配器要求 Panda **2.1.2**，并使用 JavaScript runtime 产物（`.js` 或 `.mjs`）。包入口提供 ESM、CommonJS 和 TypeScript 声明。应用代码可以使用无依赖的[独立 runtime](/zh/api/runtime/)。

[框架兼容矩阵](/zh/frameworks/)区分构建产物、浏览器交互和小程序运行时的验证范围。已有 v1 项目请按照 [2.0 迁移指南](/zh/migration/)升级。
