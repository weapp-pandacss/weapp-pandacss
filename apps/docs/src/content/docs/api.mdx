## Package entries

Every JavaScript entry supports ESM, CommonJS and corresponding TypeScript declarations. `IPostcssPluginOptions`, `PostcssImportOptions`, `PandaPostcssOptions`, `UnitConversionOptions` and unit rule/context/preset types are type exports.

| Entry | Exports |
| --- | --- |
| `weapp-pandacss` | `weappPanda`, `postcssPlugin`, `encodeClassName`, `encodeClassList`, `unitPresets`, `composeUnitRules`, configuration and unit types |
| `weapp-pandacss/panda` | `weappPanda` |
| `weapp-pandacss/postcss` | Default `postcssPlugin` factory |
| `@weapp-pandacss/runtime` | `encodeClassName`, `encodeClassList`, `createPortableRuntime` |
| `weapp-pandacss/runtime` | Same three runtime exports; compatibility entry |
| Either package's `/package.json` | Package metadata |

Use `@weapp-pandacss/runtime` in application code. It has no Panda, PostCSS, Babel or Node dependencies. The main adapter package is build tooling; the standalone runtime also suits independently published component libraries.

```ts
import { weappPanda } from 'weapp-pandacss/panda'
import postcssPlugin from 'weapp-pandacss/postcss'
import type { IPostcssPluginOptions } from 'weapp-pandacss'
import { encodeClassName } from '@weapp-pandacss/runtime'

const panda = weappPanda()
const options: IPostcssPluginOptions = {}
const postcss = postcssPlugin(options)
const authored = encodeClassName('custom/active')
```

The root entry does not export `createPortableRuntime`. Internal helpers are not public APIs. The v1 file-patching APIs, adapter configuration loader, wildcard internal paths and adapter CLI binaries were removed; see the [migration guide](/migration/).

## Unit helpers

`unitPresets` and `composeUnitRules` come from the root entry and run in build
configuration. `UnitConversionOptions` and all corresponding rule, context and
preset types are exported there too. They reuse the built-in converter; no
separate installation is needed. See [the full API](/api/postcss-plugin/#built-in-unit-conversion).

## Before using a generated API

Register both `weappPanda()` and the PostCSS adapter, run `panda codegen`, and import the generated global CSS. Keep generated runtime and CSS from the same configuration. The [Panda guide](/panda/) and [PostCSS guide](/postcss/) provide the setup.

<Aside title="Encoding boundary" icon="tag">
  Panda outputs are already encoded. Encode only raw authored names, once. The adapter changes naming and CSS output; it does not generate runtime CSS, make arbitrary dynamic styles extractable, or add support for CSS features missing from a target platform. See [troubleshooting](/troubleshooting/) when a generated class has no matching style.
</Aside>
