## Verification levels

| Area | Repository verification | Boundary |
| --- | --- | --- |
| Taro React / Vue | Final framework styles and runtime class matching | Artifact checks do not prove all interactions or visual layout |
| Uni-app | Mini-program and H5 CSS artifacts | Tailwind comparison styles use a separate pipeline |
| Weapp Vite + Wevu | Compiled WXML, components, taps and changing classes through mpcore | Headless mpcore does not emulate CSS layout |
| React Web | Production computed styles and interactions in Chromium, Firefox and WebKit | Browser behavior is not mini-program device evidence |
| Real WeChat DevTools | Opt-in rendering probes for the four mini-program examples | Requires an actual run, stable IDE and authorized AppID; simulator evidence is not physical-device evidence |
| Native WeChat, Taro Vite, other mini-program targets, App/RN | No dedicated integration acceptance | Existing framework scripts do not establish adapter support |

Use [the testing guide](https://github.com/weapp-pandacss/weapp-pandacss/blob/main/docs/testing-strategy.md) for commands and prerequisites. These levels describe test scope, rather than claim that every suite ran for your application.

## Run a repository example

From the repository root, build the adapter **and its runtime dependency** before invoking an example directly:

~~~sh
corepack enable
pnpm install --frozen-lockfile
pnpm exec turbo run build --filter=weapp-pandacss
pnpm --filter @weapp-pandacss/weapp-vite-app build
~~~

## Target-aware build script

Taro and Uni-app select generated directories using an environment variable. Set it **before Panda reads its configuration**, then pass the same value to the framework build. Setting it only inside the framework is too late for a preceding codegen process.

For a standalone project, save this source-derived helper as `scripts/run-platform.mjs`:

~~~js
import { spawnSync } from 'node:child_process'
import { createRequire } from 'node:module'
import path from 'node:path'
import process from 'node:process'

const [framework, target, ...args] = process.argv.slice(2)
if (!['taro', 'uni'].includes(framework) || !target) {
  throw new Error('Expected <taro|uni> <target> <framework arguments>')
}
const require = createRequire(path.resolve('package.json'))
const env = {
  ...process.env,
  [framework === 'taro' ? 'TARO_ENV' : 'UNI_PLATFORM']: target,
}

function run(packageName, command, commandArgs) {
  const manifest = require.resolve(`${packageName}/package.json`)
  const bin = require(manifest).bin[command]
  const result = spawnSync(
    process.execPath,
    [path.resolve(path.dirname(manifest), bin), ...commandArgs],
    { env, stdio: 'inherit' },
  )
  if (result.error) throw result.error
  if (result.status !== 0) process.exit(result.status ?? 1)
}

run('@pandacss/dev', 'panda', ['codegen'])
run(
  framework === 'taro' ? '@tarojs/cli' : '@dcloudio/vite-plugin-uni',
  framework,
  args,
)
~~~

The framework guides provide matching package scripts. Run them in the application directory. The repository uses the same approach in [examples/run-platform.mjs](https://github.com/weapp-pandacss/weapp-pandacss/blob/main/examples/run-platform.mjs); its scripts point to `../run-platform.mjs` instead.

## Generated output

Ignore `styled-system/`, framework `dist/` and Weapp Vite's `.weapp-vite/`. Commit source configuration and the layer entry stylesheet. Parallel Web and mini-program builds need independent generated directories, output directories and aliases. Do not restore an old runtime over newer CSS or encode Panda's `css()` / recipe output again.

Continue with [Panda configuration](/panda/), [PostCSS configuration](/postcss/) and [troubleshooting](/troubleshooting/).
