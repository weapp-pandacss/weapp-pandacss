This page covers the original 2.0 migration and the shared ordered-compiler update below. Version 2.0 changes class encoding and default variable naming. Old runtime, page artifacts and newly generated CSS must not be mixed. The migration replaces generated-file patching with a Panda plugin; it is more than changing an import.

## Upgrade sequence

1. Stop the project's build/watch processes that write the generated directory. Remove its old `styled-system` output, including helper backups and weapp-panda patch files.
2. Pin `@pandacss/dev`, `@pandacss/preset-base` and `@pandacss/preset-panda` to **2.2.0** for new installations. The minimum is **2.1.2**, and later stable releases are accepted with no upper version bound when all three packages match. Real consumer tests cover **2.1.2** and **2.2.0**; AST structure checks remain in place. Register `weappPanda()`, set `polyfill: false`, and use supported `.js` or `.mjs` runtime output.
3. Replace `panda codegen && weapp-panda codegen` with `panda codegen`. Remove adapter subprocesses, `codegen:done` patch hooks and platform rollback scripts.
4. Register only `weapp-pandacss/postcss: {}` for import expansion → Panda → adaptation. Optional unit conversion is configured with built-in `units` on that same plugin. Move CSS options from the old adapter configuration file into this plugin's arguments.
5. Update authored-class helpers to `@weapp-pandacss/runtime`. Encode raw authored names once, leaving `css()`, recipe, pattern and `cx()` results intact.
6. Align target environment, generated/output directories and aliases, then regenerate runtime and CSS together. Clear only the affected framework target's stale cache and rebuild.
7. Inspect final classes, selectors, token references and actual interactions on each target you support.

Do not restore the legacy runtime with rollback and then apply the new plugin. The plugin returns transformed artifacts to Panda before writing; it does not need helper backups or post-generation file edits.

## Panda configuration

~~~ts
// panda.config.ts
import { defineConfig } from '@pandacss/dev'
import { weappPanda } from 'weapp-pandacss/panda'

export default defineConfig({
  plugins: [weappPanda()],
  polyfill: false,
  presets: ['@pandacss/preset-base', '@pandacss/preset-panda'],
  include: ['./src/**/*.{js,jsx,ts,tsx,vue}'],
  preflight: false,
  outdir: 'styled-system',
  outExtension: 'mjs',
  forceImportExtension: true,
})
~~~

The full application also needs the PostCSS configuration and imported global stylesheet from [installation](/get-started/). Keep source imports consistent with the generated extension and directory.

## Replace manual class helpers

~~~ts
// Replace an old styled-system/weapp-panda/index.mjs import.
import { encodeClassList, encodeClassName } from '@weapp-pandacss/runtime'

const activeClass = encodeClassName('custom/active')
const labels = encodeClassList('a.b 中文')
~~~

The old public `weapp-pandacss/runtime` entry remains a compatible facade over the standalone implementation. It is different from the removed internal generated helper path. Install the standalone package as an application dependency when using it in application code.

| Raw input | New output |
| --- | --- |
| `a.b` | `a_wp_2e_b` |
| `a_wp_2e_b` | `a_wp_5f_wp_2e_b` |
| `1card` | `_wp_31_card` |
| `中文` | `_wp_4e2d__wp_6587_` |

Do not migrate by replacing an old escaped string with a guessed new one throughout generated files. Regenerate and let the codec operate on the original names. See [class names](/guides/class-names/).

## Removed v1 interfaces

| v1 interface | v2 replacement |
| --- | --- |
| `createContext`, `inject`, `patch` and runtime file-operation APIs | `weappPanda()` in Panda configuration |
| Adapter `defineConfig` and configuration loaders | Panda's `defineConfig`; direct PostCSS options |
| `UserConfig`, `ICreateContextOptions` and legacy configuration types | Panda configuration types and `IPostcssPluginOptions` |
| `weapp-panda` / `weapp-pandacss` CLI, codegen/init/rollback commands | Panda's codegen and normal framework scripts |
| `escapePredicate`, PostCSS `naming` and legacy encoding | Portable encoding and full paired regeneration |
| Wildcard internal path imports | Public root, `/panda`, `/postcss`, `/runtime` or standalone runtime |

The removed interfaces have no deprecated placeholder implementation. Public signatures and import forms are listed in the [API reference](/api/).

## Layers and old PostCSS options

The default ordered path needs original `@layer` information. Keep Panda `polyfill: false` and rebuild from source. It does not reconstruct layer order from old `:not(#\#)` specificity placeholders.

Explicit `removeNegationPseudoClass`, `selectorReplacement.cascadeLayers` or `cascadeLayersPluginOptions` selects legacy mode. To adopt ordered mode, remove those legacy options and use `cascadeLayers: { mode: 'ordered' }`. Mixing them is a configuration error.

Layer conversion is order compatibility, not full native cascade equivalence. Review specificity warnings and the single-root boundary in [CSS compatibility](/guides/css-compatibility/). This layer-mode choice does not introduce another class-encoding format.

## Shared ordered-compiler update

The source update replaces the local ordered core with pinned `@weapp-tailwindcss/css-compat@0.1.2` and records **minor release intent**. It does not assign or publish a new adapter version; consult the package/release for the installed version. The published guide already required imports and nesting to be expanded before adaptation. The shared core now validates that requirement for **every residual import**, including ordinary and remote imports, rather than only layer-qualified imports.

1. Keep source `@import` declarations. Check their graph is combined before Panda and the adapter, using the [PostCSS pipeline](/postcss/) or your framework's importer. Do not remove imports to make validation pass.
2. Use the default composed PostCSS plugin on Taro React/Vue, React Vite and Weapp Vite. For the Uni-app Panda virtual entry, pass the real `pandaEntry` filename and forward imported-file/Panda dependencies to watch; the virtual entry sets `units: false`, H5 also sets `adapter: false`, and the final framework pass adapts and converts units once.
3. Vendor remote styles locally or use an upstream resolver; `postcss-import` leaves remote imports unresolved. Expand nesting and preprocessor syntax before adaptation; replace `revert-layer` with explicit rules.
4. Retain existing public options and legacy selection. The old three `WP_LAYER_*` text prefixes remain; programmatic diagnostics now expose `LAYER_*` codes, source positions and context. New descriptor/wrapper compatibility warnings can make `onConflict: 'error'` reject additional risky input.
5. Regenerate and rebuild every supported target. Verify imported special-class encoding, normal unlayered precedence, important inversion and updates after editing an imported file. H5 keeps native layers; the source import graph must be fully expanded before mini-program ordered compilation. The compiler removes layers from that root. A framework can subsequently emit valid WXSS imports of independently compiled assets; those output imports are outside this input check.

No runtime migration, naming rollback or new direct application dependency on CSS compat is required. Strict/input failures carry structured diagnostics in a PostCSS `CssSyntaxError`; atomic validation is guaranteed for the independent layer stage, not for all preceding adapter mutations. See [troubleshooting](/troubleshooting/#ordinary-import-now-fails) for symptoms and checks.

## Upgrade to the zero-option PostCSS pipeline

This minor update makes the existing PostCSS entry compose imports, official Panda and adaptation by default. Replace separate `postcss-import` / `@pandacss/dev/postcss` registrations with:

~~~js
module.exports = {
  plugins: { 'weapp-pandacss/postcss': {} },
}
~~~

Keep `panda.config`, `weappPanda()`, `polyfill: false`, explicit presets matching the supported Panda version, the global `.css` layer entry and codegen scripts. H5 uses `{ target: 'web' }`; unit conversion is opt-in through built-in `units`. Custom pipelines can retain external stages by disabling the matching internal `imports`/`panda` stage, or use `{ imports: false, panda: false }` for adapter-only processing. `disabled: true` now bypasses the complete composed pipeline, while `adapter: false` still imports, generates CSS and runs configured units.

Panda discovers the config nearest the real source file before process-cwd fallback; explicit overrides belong under `panda`. Use the real `from` for custom loaders and forward dependency messages. Sass/Less/Stylus remain framework preprocessing steps, with a `.css` Panda entry. The default importer rejects raw preprocessor imports; no compiler or unit ratio is inferred. Rebuild each target and verify watch updates, class/selector matching and native H5 layers. See [the complete interface](/api/postcss-plugin/).

## Built-in unit-conversion minor update

Unit conversion now belongs to the existing PostCSS entry. Remove the separate
converter registration/dependency and move its ratio into `units`; keep empty
options if you do not need conversion. There is no platform-derived default:

~~~js
module.exports = {
  plugins: {
    'weapp-pandacss/postcss': {
      units: { rules: [{ from: 'rem', to: 'rpx', factor: 32 }] },
    },
  },
}
~~~

The stage runs after the full adapter lifecycle and before framework
postprocessing. Retain Taro `pxtransform` / NutUI `designWidth` when it owns px;
disable overlapping conversion if custom units takes over px/rpx. Uni's virtual
Panda entry sets `units: false`, then the final framework pass converts once.
Tailwind uses a converter-only pass with `adapter: false`, preserving its names.
`disabled: true` bypasses every stage; `adapter: false` retains configured units.

Default CSS tokenization fixes signed/scientific numbers and protects complete
units, strings, URLs, identifiers and deeply nested `var()` fallbacks. Callbacks
receive signed values; `minValue` compares absolute magnitude. Review custom
`unitRegex` and multi-pass rules: the first matching rule wins, one run does not
chain, and repeated processing can convert again. The root entry supplies
`unitPresets`, `composeUnitRules` and complete types without another install.
See [the full unit API](/api/postcss-plugin/#built-in-unit-conversion).

## Web/H5 and build isolation

Web/H5 retains `weappPanda()` and the composed PostCSS plugin with `target: 'web'`. It retains native layers/selectors with the same portable class naming, so there is no runtime rollback step.

Taro examples use `styled-system/weapp` and `styled-system/h5` with output under `dist/<platform>`. Uni-app examples use `styled-system/mp-weixin` and `styled-system/h5`; final directories differ for dev/build. Set the platform before codegen and resolve `styled-system` to the matching target. Never let two writers share one generated directory.

The Uni-app Tailwind comparison uses separate Panda and Tailwind pipelines; the new portable codec is not a replacement for Tailwind's own runtime naming. See [build targets](/guides/build-targets/) for environment, aliases, watch and cache handling.

## Compatibility and completion

| Capability | Boundary |
| --- | --- |
| Panda generation | Stable releases **>=2.1.2**, codegen and PostCSS automatic generation; real consumer tests cover **2.1.2** and **2.2.0** |
| Generated runtime extension | `.js` / `.mjs`; TS-only and unknown/incomplete structures are rejected |
| Portable producer coverage | `css`, `cva`, `sva`, named/slot recipes, compounds, patterns and styled metadata |
| Runtime behavior | `cx` remains joining; raw style objects and metadata retain Panda semantics |
| Application JS | Framework must bundle/transpile for the selected runtime |
| Source-level raw-class inlining | Unsupported when it bypasses the generated runtime |
| Package consumption | ESM/CJS public entries and corresponding declarations |
| CSS reprocessing | Keep the portable generation marker |

Confirm a clean build, a second codegen, recipe/slot state changes and the final token declarations. Validate the real IDE/device where required; source coverage and artifact matching alone do not prove pixel layout. If a stage fails, follow [troubleshooting](/troubleshooting/) rather than retaining mixed old/new output.
