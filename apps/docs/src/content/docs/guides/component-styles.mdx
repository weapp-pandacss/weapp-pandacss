## Component isolation

A class can be correct while its global WXSS is blocked by a component boundary. Check both the stylesheet's import location and the framework's isolation setting.

The Weapp Vite + Wevu example keeps Panda CSS at application level and explicitly allows it into its button component:

~~~ts
// Inside the component's <script setup lang="ts">.
defineComponentJson({
  component: true,
  styleIsolation: 'apply-shared',
})
~~~

For a native WeChat component, the corresponding option belongs in the component definition's `options`:

~~~js
Component({
  options: { styleIsolation: 'apply-shared' },
  // properties, data and methods...
})
~~~

`apply-shared` permits page styles to affect the component while keeping component styles from affecting the page. Select an isolation policy intentionally; changing to `shared` has a wider effect. Framework-generated component scopes or `scoped` styles are a separate mechanism. Inspect the emitted selectors instead of assuming a source class survives every scoping step unchanged.

When distributing components, document their expected isolation and shared stylesheet imports. The runtime encoder cannot bypass style isolation. Native `externalClasses` can expose a supported styling surface, but callers still need matching names and accessible styles. See WeChat's [component templates and styles](https://developers.weixin.qq.com/miniprogram/dev/framework/custom-component/wxml-wxss.html).

## Units and design scale

Class encoding does not choose a dimension scale. Unit conversion is built in,
with `units: false` by default on both targets. To opt into `1rem = 32rpx`, use:

~~~js
module.exports = {
  plugins: {
    'weapp-pandacss/postcss': {
      units: { rules: [{ from: 'rem', to: 'rpx', factor: 32 }] },
    },
  },
}
~~~

No extra converter installation is needed. The stage runs after complete adapter
processing and before framework postprocessing; it covers generated Panda token
values, compiled Sass/Less/Stylus CSS and imported third-party declarations in the
same root. The ratio is your design choice, not the browser's root font size.

| Input with this rule | Mini-program `to: 'rpx'` | H5 `to: 'px'` |
| --- | --- | --- |
| `1rem` | `32rpx` | `32px` |
| `0.5rem` | `16rpx` | `16px` |
| `-2rem` | `-64rpx` | `-64px` |
| `1e-3rem` | `0.032rpx` | `0.032px` |

For the H5 column change `to` to `px`, keeping `factor: 32`. The React Web example
leaves conversion disabled, so the browser handles rem. Rules also support regex
and function matchers, arbitrary length units, precision, property/selector
filters and signed transform callbacks. Relative units such as `em`, `ch`, `vw`
and container units require an explicit project basis; the build cannot infer
runtime font metrics or a device's viewport.

Default token matching protects strings, URLs and identifiers, and skips the
entire `var()` fallback at any depth. A custom-property declaration such as
`--gap: 0.5rem` becomes `--gap: 16rpx`, while `var(--gap, 0.5rem)` keeps its fallback.
The first matching rule wins and output is not chained in one run. Reprocessing
can convert again; the portable class marker does not mark unit conversion.
`exclude` uses the root-entry path, not each imported declaration's path. See
[all options and source-aware callbacks](/api/postcss-plugin/#built-in-unit-conversion).

Taro still applies its own `designWidth` / `pxtransform`, including the examples'
NutUI per-file `designWidth` baseline. The examples convert rem first and let
Taro own px. If custom `units` rules take over overlapping px/rpx conversion,
disable the corresponding Taro `pxtransform` rather than converting twice.
Uni-app's virtual Panda entry uses `units: false`, with conversion only in the
final framework pass; its Tailwind entry uses a converter-only pass without Panda
class encoding. See [entry isolation](/guides/build-targets/#panda-and-tailwind-entry-isolation).

Runtime inline styles bypass PostCSS. Choose their intended `rpx`, `px` or `%`
directly. Compare final declarations and rendered dimensions on the selected
target; class/WXSS matching alone does not verify physical-device layout. See
WeChat's [WXSS reference](https://developers.weixin.qq.com/miniprogram/dev/framework/view/wxss.html).

## Third-party styles

The adapter's naming pass covers every class selector in the processed root, including authored and vendor styles. Ordinary identifiers usually stay readable, but special characters, leading digits/hyphens and the literal `_wp_` marker change.

If a library produces class strings at runtime, transforming only its CSS can break it. Before including that stylesheet in the adapter pipeline:

1. Identify which code supplies its class names and which file supplies its selectors.
2. Check whether those names are unchanged by the portable codec.
3. Use the library's own adaptation workflow where it has one, or keep its entry separate from Panda's processing.
4. Compare a rendered node's class with the final selector after framework scoping and unit conversion.

Do not repair a vendor mismatch by encoding all class strings again; Panda-generated values may already be encoded. The Taro examples use NutUI, but their current integration is not a guarantee for every UI library, generated selector or version.

## Resets, CSS Modules and overrides

The installation baseline sets `preflight: false` to avoid introducing a global reset by default. Some repository examples enable preflight intentionally. If you enable it, inspect native tags and third-party controls after the adapter replaces root and universal selectors.

The Taro examples disable CSS Modules for their shared Panda styles. Applying another class-renaming system requires a matching runtime mapping; the portable adapter does not automatically integrate every CSS Modules pipeline. Keep the application-level Panda stylesheet in a global path.

Use recipe variants or a documented component styling surface for overrides. Cross-layer order does not always defeat a high-specificity vendor rule in WXSS. Check the [specificity boundary](/guides/css-compatibility/#specificity-is-a-compatibility-boundary) before relying on layers to override a library.

## Panda with Tailwind

The Uni-app example keeps Panda and Tailwind entries separate, with each runtime paired to its own selector encoding. Do not send Tailwind output through the Panda naming pass. The actual virtual-entry and processing order are explained in [build targets](/guides/build-targets/#panda-and-tailwind-entry-isolation).

Verify a component's initial and selected variants, token variables and visible dimensions inside its actual boundary. For an isolated component failure use [troubleshooting](/troubleshooting/#styles-work-on-a-page-but-not-in-a-component).
