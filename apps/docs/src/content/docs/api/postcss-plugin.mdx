## postcssPlugin(options)

```ts
import postcssPlugin from 'weapp-pandacss/postcss'
import type { IPostcssPluginOptions, PandaPostcssOptions, PostcssImportOptions } from 'weapp-pandacss'

const plugin = postcssPlugin()
```

The factory accepts an optional `IPostcssPluginOptions` object and returns a PostCSS plugin. The root package exposes the same factory as `postcssPlugin`. Both `postcssPlugin()` and `postcssPlugin({})` use the defaults below.

```ts
declare function postcssPlugin(options?: IPostcssPluginOptions): import('postcss').Plugin
```

```js
const postcssPlugin = require('weapp-pandacss/postcss')
const plugin = postcssPlugin()
```

With no options, the factory composes **CSS import expansion → official Panda generation → mini-program adaptation**. Register only `weapp-pandacss/postcss: {}` in PostCSS, retain `weappPanda()` in Panda's config, and load a global `.css` layer entry. Unit conversion is built in through opt-in `units`, disabled by default. See the [configuration guide](/postcss/) for project discovery and framework preprocessors. The independent ordered layer core keeps a pure AST boundary; the composed plugin's importer owns file reads before it.

## Complete options

All fields are optional. Nested adaptation objects inherit omitted defaults; replacement arrays replace the default array rather than appending to it. `imports`, `panda` and `units` are forwarded without recursive merging, preserving regexes and callbacks.

| Field | Type | Default | Effect |
| --- | --- | --- | --- |
| `imports` | `boolean \| PostcssImportOptions` | `true` | Expands imports before Panda; upstream fields below |
| `panda` | `boolean \| PandaPostcssOptions` | `true` | Runs official Panda; upstream fields below |
| `adapter` | `boolean` | `true` | Runs naming, markers and target CSS adaptation |
| `units` | `false \| UnitConversionOptions` | `false` | Runs generic unit conversion after complete adaptation; all fields below |
| `target` | `'weapp' \| 'web'` | `'weapp'` | Selects platform CSS behavior; class names match in both targets |
| `disabled` | `boolean` | `false` | Bypasses imports, Panda, adaptation and unit conversion |
| `cascadeLayers.mode` | `'ordered' \| 'legacy'` | `'ordered'` unless legacy options are passed | Chooses mini-program layer compilation |
| `cascadeLayers.onConflict` | `'warning' \| 'error'` | `'warning'` | Severity of ordered-layer compatibility diagnostics |
| `selectorReplacement.root` | `string \| string[]` | `'page'` | Replaces `:root` and `:host` in mini-program CSS |
| `selectorReplacement.universal` | `string \| string[]` | `['view', 'text']` | Expands `*` in mini-program CSS |
| `selectorReplacement.cascadeLayers` | `string` | `'n'` | Legacy replacement tag when negation placeholders are retained |
| `removeNegationPseudoClass` | `boolean` | `true` | Legacy removal of generated `:not(#\#)` placeholders |
| `cascadeLayersPluginOptions` | Object; fields below | `{}` | Options passed to the legacy csstools layer plugin |
| `isPseudoClassPluginOptions` | Object; fields below | `{}` | Options passed to csstools `:is()` transformation in mini-program mode |

Use arrays for multiple root or universal replacement tags:

```ts
const options: IPostcssPluginOptions = {
  selectorReplacement: {
    root: ['page', 'body'],
    universal: ['view', 'text', 'button'],
  },
}
```

Choose replacements for components your platform uses. This transforms selector syntax; it does not establish native component styling permissions or style isolation.

## Import and Panda options

`imports: true` uses the defaults of `postcss-import@17.0.0`, with a loader guard against raw preprocessor imports. `false` disables it. Object options are forwarded to the importer; upstream behavior and callbacks are documented in [postcss-import](https://github.com/postcss/postcss-import#options).

| `imports` field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `root` | `string` | `process.cwd()` | Importer search root; relative import base comes from the real source file. Supply explicitly for string/virtual input |
| `path` | `string \| string[]` | `[]` | Additional search paths |
| `filter` | `(id: string) => boolean` | Accept all | Leave rejected imports unresolved; mini-program ordered mode will reject residual imports |
| `resolve` | `(id, basedir, options) => string \| string[] \| Promise` | Upstream resolver | Resolve an import, including package CSS |
| `load` | `(filename, options) => string \| Promise<string>` | Read UTF-8 CSS with preprocessor guard | Provide already compiled CSS; custom loaders own extra dependencies |
| `plugins` | `AcceptedPlugin[]` | `[]` | Process each imported CSS file before combining it |
| `skipDuplicates` | `boolean` | `true` | Deduplicate equal content/files in the same import scope |
| `addModulesDirectories` | `string[]` | `[]` | Add resolution directories alongside `node_modules` and `web_modules` |
| `warnOnEmpty` | `boolean` | `true` | Warn when an imported file is empty |

`panda: true` lazily loads the official Panda 2.2.0 PostCSS plugin. `false` disables generation. These are its complete options:

| `panda` field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `cwd` | `string` | Discovered config directory, then process cwd | Panda project root |
| `configPath` | `string` | Closest config above the real source file, then cwd discovery | Explicit config path, relative to `cwd` when relative |
| `outdir` | `string` | Panda config's `outdir` | Override the generated artifact directory |
| `allow` | `RegExp[]` | Unset | Allow selected `node_modules` CSS through the official processing guard |

For exact callback types, use `Exclude<IPostcssPluginOptions['imports'], boolean | undefined>` and `Exclude<IPostcssPluginOptions['panda'], boolean | undefined>`; the published declarations resolve without consumers installing extra type packages. Explicit `cwd` or `configPath` takes precedence, and invalid explicit configuration fails directly. A no-file CSS string still supports adaptation; the official Panda stage skips generation. Relative imports require a real `from` or explicit importer root. Discovery does not invent physical filenames for virtual/remote inputs.

```ts
postcssPlugin({ imports: false, panda: false }) // adapter only
postcssPlugin({ adapter: false }) // import + Panda only
postcssPlugin({ panda: { cwd: '/workspace/app' } })
postcssPlugin({ imports: { skipDuplicates: false } })
```

Before generation, the plugin reports duplicate official Panda registration and incorrect external stage order. External Panda must precede adaptation; an external-only importer must precede generation and adaptation. A trailing framework importer is allowed when the built-in importer has already expanded the graph. Remove the duplicate or disable the internal stage and place its external owner before the remaining stages. `disabled: true` bypasses the entire pipeline; `adapter: false` only skips adaptation and still expands imports, generates Panda CSS and runs explicitly configured `units`. `target: 'web'` retains both defaults and adapts class names while preserving native layers.

## Built-in unit conversion

`units?: false | UnitConversionOptions` defaults to `false` for both targets.
The adapter includes `postcss-rule-unit-converter` as a runtime dependency;
applications do not install or register it separately. Enable a rule object to
convert arbitrary CSS length units after imports, Panda and the **full adapter
lifecycle**, before framework postprocessing. No target implies a ratio.

```js
module.exports = {
  plugins: {
    'weapp-pandacss/postcss': {
      units: {
        rules: [{ from: 'rem', to: 'rpx', factor: 32 }],
      },
    },
  },
}
```

`0.5rem` becomes `16rpx`. `units: {}` has no rules and leaves values unchanged.
`adapter: false` still runs configured units; `disabled: true` bypasses everything.
For conversion alone, use the same entry with `imports: false`, `panda: false`
and `adapter: false`. Synchronous adaptation/conversion requires disabling the
asynchronous import/Panda stages with `imports: false, panda: false`; omitting
`from` does not disable the importer. A CSS string needs no fabricated filename.
Source maps, diagnostics and file dependencies remain in
the outer PostCSS result, and framework declaration visitors see converted values.

### Complete unit options

These are the full upstream `UnitConversionOptions`; supplied objects are
forwarded without recursive merging. Ratios are build-time rules: conversions of
font-, container- or viewport-relative units require the project's own basis.

| `units` field | Type | Default | Behavior |
| --- | --- | --- | --- |
| `rules` | `readonly ConversionRule[]` | `[]` | Ordered rules; first matching rule wins |
| `unitRegex` | `RegExp` | Unset | Replaces default CSS tokenization entirely |
| `unitPrecision` | `number` | `5` | Decimal rounding; values outside `0..100` skip rounding |
| `minValue` | `number` | `0` | Minimum absolute source magnitude; rules can override it |
| `keepZeroUnit` | `boolean` | `false` | Keep the target unit on zero instead of emitting `0` |
| `selectorBlackList` | `readonly (string \| RegExp)[]` | `[]` | Skip matching selectors; string entries match substrings |
| `propList` | `readonly (string \| RegExp)[]` | `['*']` | Property filter with wildcards, regex and `!` exclusions |
| `replace` | `boolean` | `true` | Replace values; `false` appends fallback declarations, deduplicated by property, value and `!important` |
| `mediaQuery` | `boolean` | `false` | Also convert lengths in `@media` parameters |
| `exclude` | `readonly (string \| RegExp)[] \| ((filePath: string) => boolean)` | `[/node_modules/i]` | Skip the entire root entry, not each imported source |
| `disabled` | `boolean` | `false` | Disable only conversion; outer `disabled` disables the whole pipeline |

### Rules, callbacks and helpers

```ts
import { composeUnitRules, unitPresets } from 'weapp-pandacss'
import type { ConversionRule, RuleContext, UnitConversionOptions } from 'weapp-pandacss'

type UnitMatcher = string | RegExp | ((unit: string) => boolean)
// ConversionRule: { from: UnitMatcher; to?: string; factor?: number;
//                   minValue?: number; transform?: RuleTransform }
// RuleTransform: (value: number, context: RuleContext) =>
//                number | { value: number; unit?: string } | undefined

const units: UnitConversionOptions = {
  rules: composeUnitRules(
    unitPresets.remToRpx({ rootValue: 32 }),
    { from: /^px$/, to: 'rpx', factor: 2 },
    {
      from: unit => unit === 'em',
      to: 'rpx',
      minValue: 0.25,
      transform(value, context: RuleContext) {
        return value * (context.prop === 'letter-spacing' ? 8 : 16)
      },
    },
  ),
}
const rule: ConversionRule = { from: 'rem', to: 'px', factor: 16 }
```

`unitPresets` is the upstream `presets` object; `composeUnitRules(...groups)` is
upstream `composeRules`, flattening rules and preset groups in order. Common
presets include `remToPx`, `remToRpx`, `pxToRem`, `pxToRpx`, `rpxToPx`, viewport
conversions, `unitsToPx`, and `pxPresetGroup` / `rpxPresetGroup` /
`viewportPresetGroup` / `webPresetGroup`. Font or viewport options can be resolved
from the current PostCSS `Input`; this is the root entry, not an imported file.
See the [upstream preset and API reference](https://github.com/icelib/postcss-plugins/blob/main/packages/postcss-rule-unit-converter/API.md).

The root exports `UnitConversionOptions`, `ConversionRule`, `ConvertedValue`,
`RuleContext`, `RuleGroup`, `RuleTransform`, `UnitMatcher`, `UnitTransform`,
`GlobalUnitTransform`, `UnitRule`, `UnitMap`, `NumericResolver`, `PresetOptions`,
`PresetFactory`, `PresetGroupFactory`, `LinearPresetOptions`, `RatioOptions`,
`RemBasedPresetOptions`, `RemToViewportPresetOptions`,
`RemToViewportHeightPresetOptions`, `ViewportPresetOptions`,
`ViewportHeightPresetOptions`, `UnitMapPresetOptions`, `PxPresetGroupOptions`,
`RpxPresetGroupOptions` and `ViewportGroupOptions`. Types resolve through the
adapter's runtime dependency; no extra converter or type installation is needed.

### Matching and repeated processing

Default matching uses complete CSS dimension/percentage tokens. Signed and
scientific values are parsed correctly: `-2rem` passes `-2` to callbacks and
`1e3rem` passes `1000`. `minValue` compares `Math.abs(value)`. Unit names are
decoded and lowercased before string, regex or function matching, while
`context.rawUnit`, `rawValue` and `match` preserve source spelling. A `rem` rule
leaves `2remfoo` and the identifier `foo2rem` unchanged.

Strings, comments and URLs are protected, including escaped quotes and uppercase
`URL()`. The entire `var()` function and its fallback are skipped at every nesting
depth; dimensions in `calc()` and `min()` outside `var()` can convert. Panda
custom-property declarations can convert, but `var()` fallbacks remain native.

The first matching rule is final even if its callback returns `undefined` or its
threshold is not met. Generated values do not chain into later rules in the same
run. Processing again may convert them, including when the portable class marker
is present: that marker prevents repeated class encoding, not unit conversion.
Assign one owner per input unit in multi-pass builds.

An explicit `unitRegex` bypasses tokenization and all its protections. Capture the
number in group 1 and unit in group 2; a missing `g` flag is added. The custom
regex owns signs, scientific notation, token boundaries and string/URL/`var()`
skipping. Invalid capture structure throws instead of silently doing nothing.

`context` also includes `root`, root-entry `input` / `filePath`, and the current
`decl`, `rule`, `prop`, `selector` or `atRule`. Use
`context.decl?.source?.input.file` for an imported declaration's original path;
`exclude` is evaluated only against the root entry. Return `undefined` from a
transform to retain a per-source value. Media parameters have no `decl`.

## csstools options

### cascadeLayersPluginOptions

Applies only to `mode: 'legacy'`. The adapter defaults to `{}`; the installed `@csstools/postcss-cascade-layers` supplies the following defaults.

| Field | Type | Upstream default | Meaning |
| --- | --- | --- | --- |
| `onRevertLayerKeyword` | `'warn' \| false` | `'warn'` | Warns about `revert-layer` handling |
| `onConditionalRulesChangingLayerOrder` | `'warn' \| false` | `'warn'` | Warns when conditional rules can change layer order |
| `onImportLayerRule` | `'warn' \| false` | `'warn'` | Warns about layer-qualified imports |

These switches configure legacy warnings; they do not make unsupported input equivalent to native layers. Ordered mode uses its own diagnostics and hard errors instead.

### isPseudoClassPluginOptions

Applies to mini-program mode in either layer pipeline. Web keeps `:is()` unchanged.

| Field | Type | Upstream default | Meaning |
| --- | --- | --- | --- |
| `preserve` | `boolean` | `false` | Keeps the original notation alongside transformed output when enabled |
| `onComplexSelector` | `'warning'` | Unset | Enables warnings for complex selectors inside `:is()` |
| `onPseudoElement` | `'warning'` | Unset | Enables warnings for pseudo-elements inside `:is()` |
| `specificityMatchingName` | `string` | `'does-not-exist'` | Selector name used for specificity adjustment |

The spelling is `'warn'` for legacy layer switches and `'warning'` for the `:is()` switches. These option types follow the installed csstools plugins; they are not separately exported by `weapp-pandacss`.

## Target behavior

| Transformation | `weapp` | `web` |
| --- | --- | --- |
| Portable class selector encoding | Yes | Yes |
| Portable CSS marker | Yes | Yes |
| ASCII CSS variable validation | Yes | No |
| `:root` / `:host` / `*` replacement | Yes | No |
| `:where()` expansion and `:is()` processing | Yes | No |
| Layer flattening | Ordered or legacy | Native layers retained |

Mini-program `:where()` is expanded into ordinary selectors, so its native zero-specificity semantics are not retained. The selector transformer also changes `~` to `+` when the preceding selector node is not a class: `* ~ *` and `.peer:hover ~ .target` are examples. A plain `.peer ~ .target` retains `~`. Test peer and state selectors on the actual target; syntax adaptation is not a full Web selector polyfill.

When `disabled: true`, the CSS is left untouched. Encoded runtime names can then fail to match raw selectors. Use it only when that stylesheet does not need adaptation or another pipeline owns matching names.

## Ordered and legacy selection

Ordered is the default and delegates layer compilation to the pinned `@weapp-tailwindcss/css-compat@0.1.1` core. The compatibility adapter preserves the existing options and diagnostic text prefixes. It compiles layer source order without creating specificity placeholders. Explicitly supplying any of these fields selects legacy when no mode is specified:

- `removeNegationPseudoClass`, including `true`.
- `selectorReplacement.cascadeLayers`, including `'n'`.
- `cascadeLayersPluginOptions`, including `{}`.

```ts
postcssPlugin({ cascadeLayers: { mode: 'ordered', onConflict: 'error' } })

postcssPlugin({
  cascadeLayers: { mode: 'legacy' },
  removeNegationPseudoClass: false,
  selectorReplacement: { cascadeLayers: 'n' },
})
```

Legacy continues to use `@csstools/postcss-cascade-layers`; it does not delegate to the shared package's `/legacy` entry. In legacy mode, `removeNegationPseudoClass: true` deletes generated `:not(#\#)` placeholders; false replaces their inner selector with the configured tag, yielding `:not(n)` by default. Ordinary authored `:not(...)` is preserved.

Explicit `mode: 'ordered'` combined with any legacy field is a configuration error. This check runs when the factory resolves options, before `disabled` or Web processing can skip transformations. Remove the old fields or select legacy. `cascadeLayers.onConflict` applies to ordered mode only.

## Layer order and diagnostics

Ordered compilation registers layers in first-declaration order. Normal declarations follow that order, then unlayered rules. Important declarations use reversed layer order, with unlayered important declarations first. Nested, dotted, anonymous and repeated layers are supported; source order within a layer is retained.

WXSS selector specificity still takes precedence over this output order. The compiler reports potential differences conservatively; a warning does not prove selectors match the same element.

| Structured code | Compatible text prefix | Trigger and handling |
| --- | --- | --- |
| `LAYER_SPECIFICITY` | `WP_LAYER_SPECIFICITY` | A lower-priority layer has a more specific selector for potentially overlapping properties; align specificity and inspect matching rules |
| `LAYER_CONDITIONAL_ORDER` | `WP_LAYER_CONDITIONAL_ORDER` | A layer is first registered inside a condition; declare the complete named order outside conditions |
| `LAYER_SELECTOR_UNKNOWN` | `WP_LAYER_SELECTOR_UNKNOWN` | A functional selector cannot be reliably analyzed; review target support and affected rules |
| `LAYER_DESCRIPTOR_ORDER` | No old prefix | Cross-layer descriptor definitions have duplicate or uncertain identities; review their registration semantics |
| `LAYER_WRAPPER_SEMANTICS` | No old prefix | A wrapper has semantics the compiler cannot establish; review the wrapper instead of assuming flattening preserves it |

`onConflict: 'error'` promotes these compatibility warnings to build failures. Invalid input still fails in warning mode. The three existing `WP_LAYER_*` prefixes remain in human-readable warning/error text; programmatic `warning.code` uses the shared `LAYER_*` identifier.

Core warnings include a `diagnostic` object with `code`, `severity`, `message`, `suggestion` and `source` (`file`, `line`, `column` when available). `related`, `layer`, `selector` and `property` add context when applicable. These are structured fields on emitted messages, not new `IPostcssPluginOptions` fields or newly exported adapter types. Programmatic consumers can inspect both the PostCSS text and the original diagnostic. The following example is JavaScript: the base PostCSS `Warning` type does not declare these extra fields, so TypeScript callers must narrow or locally assert them before access:

```js
import postcss from 'postcss'
import postcssPlugin from 'weapp-pandacss/postcss'

// sourceCss is the original entry text; from must identify its real location.
const result = await postcss([postcssPlugin()]).process(sourceCss, {
  from: 'src/app.css',
  to: 'dist/app.wxss',
})

for (const warning of result.warnings()) {
  console.warn(warning.toString(), warning.code, warning.diagnostic)
}
```

Failures reported by the shared core, including strict diagnostics and invalid input, throw a PostCSS `CssSyntaxError` with `code`, the first error-severity `diagnostic`, the full `diagnostics` array and the original compiler error in `cause`. The adapter's configuration, variable and Panda-polyfill guards retain their own existing errors; do not assume every adapter error has core diagnostic fields. Existing conflict text remains compatible and source positions are preserved when provided. The standalone layer stage validates before committing AST changes, including strict diagnostic failures. This atomicity applies to **that layer stage only**: earlier import/Panda or adapter selector/naming stages may already have modified the root. Do not catch an error and publish a partially processed adapter root.

## Inputs that fail ordered compilation

These errors fail even when `onConflict` is `'warning'`.

| Input | Required action |
| --- | --- |
| `LAYER_IMPORT`: any residual `@import`, including plain/layer/remote imports | Expand the complete graph before the adapter; vendor remote CSS or resolve it upstream |
| `LAYER_NESTING`: nested style rules, `&`, or layer blocks inside style rules | Expand nesting before the adapter |
| `LAYER_REVERT`: `revert-layer` values | Replace with an explicit value; use native layers on Web where appropriate |
| Already polyfilled `:not(#\#)` selectors | Keep Panda `polyfill: false` and regenerate original layers, or explicitly select legacy |
| `LAYER_NAME`: invalid layer names, anonymous statements without a block, or multiple names on a block | Correct the layer declaration |
| `LAYER_PREPROCESSOR`: remaining conditional-compilation control comments | Consume `#if` / `#else` / `#endif` directives in the preprocessor before adaptation |
| Layer blocks inside descriptor at-rules, stray declarations, or import/namespace inside layers or conditions | Correct the CSS structure |

The shared core also reserves `LAYER_OPTIONS` and `LAYER_INPUT_STAGE` for invalid compiler options or input explicitly declared already polyfilled; these are not extra public adapter settings. Keep the documented import/nesting/Panda sequence and inspect the original diagnostic if either occurs.

Some validation, including imports, nesting and `revert-layer`, runs even if the input has no `@layer` block. Quoted text such as `content: "revert-layer"` is not treated as the keyword.

## Naming, variables and repeated processing

The adapter encodes class selectors using the same contract as the [runtime](/api/runtime/). Keep authored selectors raw with normal CSS escaping. A top-level `/*! weapp-pandacss:portable-v1 */` comment persists the naming marker across parse/serialize passes. Reprocessing marked output does not encode it again; do not strip that marker before another adapter pass.

Mini-program custom property declarations, `var()` references and `@property` names must match ASCII `--[A-Za-z0-9_-]+`. Invalid identifiers throw `Unsupported mini-program CSS variable`. This also checks nested `var()` fallbacks and marked Web CSS subsequently processed for a mini-program. Text inside quoted strings and URLs is not a variable reference. The adapter does not rename custom properties; Panda's `hash.cssVar` handles generated tokens.

Layer ordering is local to one PostCSS root. Independent stylesheets, component styles and processor calls do not share a layer registry. Combine inputs before adaptation when their relative layer order matters, then configure component style isolation separately.
